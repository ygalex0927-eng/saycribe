# Saycribe 共享识别接口（契约 v1，2026-10-30）

适用：Linux / Windows / 安卓 / iOS / Mac-Intel。Mac 主 App 目前仍用 `Sources/Suikou/Recognizer.swift` 直连 sherpa-onnx C API，行为与本契约一致。

- **Rust 平台（Linux/Windows）**：直接依赖 `platforms/core`（crate `saycribe-core`），用 `asr::Recognizer`、`vad::Segmenter`、`pipeline::Session`。
- **其他语言（JNI/Swift/C#/C++）**：按 C 头文件 `platforms/core/include/saycribe_asr.h` 包一层。C ABI 已实现：`platforms/core/src/ffi.rs`，crate-type 含 cdylib/staticlib。

## 1. 输入
| 项 | 约定 |
|---|---|
| 采样率 | 16000 Hz（`SC_ASR_SAMPLE_RATE`），其他采样率返回 `SC_ERR_AUDIO_FORMAT`；平台层自己重采样 |
| 声道 | 单声道（多声道先平均混成单声道） |
| 位深 | float32，取值 [-1,1]；int16 请除以 32768 |
| 单次上限 | 300 秒（Mac `AudioRecorder.maxSamples`）；建议单段 ≤30 秒 |
| 模式 | 只有**离线一次性解码**（SenseVoice 不是流式模型）。"准流式"＝边录边喂 VAD，每切出一段就识别一段 |

### 分段规则（Silero VAD）
窗口 512 样本（32ms）；threshold 0.5；min_silence 0.45s（停顿超过即切段）；min_speech 0.25s（契约统一；Mac Swift VoiceDetector 仍用 0.3，本轮不改）；max_speech 12s（超长强制切）；VAD 内部缓冲 120s。录音结束调 finish 冲刷尾部。短句（<约 12s 且只有一段）也可以不走 VAD，整段直接 transcribe。

## 2. 输出
`sc_result`：`text`（已 trim、ITN 后）、`lang`（如 `<|zh|>`；sherpa-onnx 2.0.1 Rust 包装未暴露 C 的 lang 字段，当前从 tokens 推断，可能为空）、`audio_seconds`、`decode_ms`、`start_sample`（段起点样本下标，÷16000 得秒）。**没有逐字时间戳**，只有段级起点。空音频/纯静音返回 `SC_OK` + 空串，不算错。

### 错误码
| 码 | 名称 | 含义 / 平台处理 |
|---|---|---|
| 0 | SC_OK | 成功 |
| -1 | INVALID_ARG | 空指针/长度非法，程序 bug |
| -2 | MODEL_MISSING | 模型没下载 → 引导下载（见 docs/模型下载.md） |
| -3 | MODEL_LOAD | 模型损坏/sha256 不符 → 删掉重下 |
| -4 | AUDIO_FORMAT | 采样率不是 16k |
| -5 | AUDIO_TOO_LONG | >300s，请分段 |
| -6 | DECODE | 解码无结果 |
| -7 | BUSY | 同一识别器被并发调用 |
| -8 | CANCELLED | 已取消 |
| -99 | INTERNAL | 其他 |

Rust 侧对应 `CoreError::Model`（-2/-3）、`CoreError::Asr`（-4/-6）、`CoreError::Io`（-2）。中转错误另见 docs/中转接口.md，不在本接口内。

## 3. 模型路径约定
`<data_dir>/models/<model_id>/model.int8.onnx`、`tokens.txt`；VAD：`<data_dir>/models/silero_vad.onnx`（`paths.rs` 的 `models_dir()`，`ModelManager` 负责下载+sha256）。模型版本：`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09`。Mac 主 App 用 app bundle 内 `Resources/models/`。iOS/安卓由平台层把路径传进 `model_dir`，core 不假设目录。

## 4. 线程 / 生命周期 / 并发
- 识别器加载约 226MB 模型，耗时 1–3 秒、内存约 300MB：**进程内只建一个，App 启动时后台预加载，退出时 destroy**。
- 同一识别器**不可并发 transcribe**（实现内加锁，抢不到返回 BUSY 或排队）；多段按 seq 串行识别即可（单段解码约百毫秒级）。
- 分段器每次录音一个（或 reset 复用），只在一个线程里用。
- num_threads 默认 4；手机建议 2。
- 所有返回的字符串/结果由库分配，必须用对应的 `*_free/destroy` 释放；`sc_status_message` 是静态串不用释放。

## 5. C 用法
```c
sc_recognizer_config rc; sc_recognizer_config_default(&rc); rc.model_dir = dir;
sc_recognizer *r; if (sc_recognizer_create(&rc, &r) != SC_OK) puts(sc_last_error());
sc_vad_config vc; sc_vad_config_default(&vc); vc.silero_model = vad_path;
sc_segmenter *s; sc_segmenter_create(&vc, &s);
// 录音回调里：
int32_t ready; sc_segmenter_push(s, pcm, n, &ready);
sc_segment seg; while (sc_segmenter_pop(s, &seg)) {
  sc_result *res; if (sc_recognizer_transcribe(r, seg.samples, seg.n, 16000, &res) == SC_OK) { use(res->text); sc_result_free(res); }
}
// 松开热键：sc_segmenter_finish(s, &ready); 再 pop 一轮；然后按顺序拼接，送中转 /v1/clean（带 session_id/seq/final）
```

## 6. 与 Mac 现有代码对应
| 契约 | Mac Swift | Rust core |
|---|---|---|
| sc_recognizer_create | `Recognizer.init(modelDir:language:)` | `asr::Recognizer::new` |
| sc_recognizer_transcribe | `Recognizer.recognize(_:)` → (text, lang) | `Recognizer::transcribe` → Transcript（暂无 lang） |
| sc_segmenter_create | `VoiceDetector.init(model:minSilence:)` | `vad::Segmenter::new` |
| sc_segmenter_push/pop | `VoiceDetector.accept(_:)` | `Segmenter::push` |
| sc_segmenter_finish | `VoiceDetector.flush()` | `Segmenter::finish` |
| sc_segmenter_speaking | `VoiceDetector.isSpeaking` | `Segmenter::speaking` |
| 16k 重采样 | `AudioRecorder`（AVAudioConverter） | 平台层负责 |
