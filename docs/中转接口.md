# Saycribe 中转接口协议 v1.1（2026-10-30）

> v1.1 变更：token 增加 `platform`（mac/windows/linux/ios/android），按设备签发/吊销，新增按用户列设备；新增 `GET /health`；正式地址已上线；客户端中转地址必须可配置。

中转 = 牙膏哥阿里云 ECS（120.24.176.206）上的独立服务 `saycribe-relay`。客户端只负责识别（SenseVoice），整理/改写/翻译/同传全部走中转；客户端不持有 DeepSeek Key，也不指定模型。

- 正式地址（已上线）：`https://saycribe-api.motomotos.com`（Let's Encrypt 证书，HTTP 自动 301 到 HTTPS）。服务本体只监听服务器本机 `127.0.0.1:18780`。
- **各客户端（Mac/Windows/iOS/Android/Linux）的中转地址必须做成可配置项**（设置页/配置文件），默认值 `https://saycribe-api.motomotos.com`，便于以后换域名、加海外节点或本地调试。
- 所有请求/响应 `Content-Type: application/json; charset=utf-8`，UTF-8。

## 1. 鉴权（设备 token）
- 每台设备一个 token，格式 `sct_<24字节 base64url>`，请求头 `Authorization: Bearer <token>`。
- 服务端只存 token 的 SHA-256，记录 `token_id / user / platform / device / created / revoked`。一台设备一个 token，按设备签发、按设备吊销，互不影响。
- `platform` 必填，取值 `mac | windows | linux | ios | android`，其他值返回 400。
- **签发**（管理员）：服务器上 `saycribe-relay-admin issue --user <用户> --platform <平台> --device <设备名>`，或
  `POST /v1/admin/tokens`，头 `Authorization: Bearer <ADMIN_TOKEN>`，body `{"user":"zjh","platform":"mac","device":"mac-mini"}` → `{"token_id":"t_xxx","token":"sct_..."}`（明文只返回这一次）。
- **吊销**：`POST /v1/admin/tokens/<token_id>/revoke`（或 CLI `revoke <token_id>`），立即生效。
- **列表**：`GET /v1/admin/tokens[?user=<用户>]`（不含明文，含已吊销）。
- **按用户列设备**：`GET /v1/admin/users/<用户>/devices` → `{"user":"zjh","devices":[{"token_id","platform","device","created","revoked":null}]}`（只列未吊销）。CLI：`saycribe-relay-admin list <用户>`。
- 管理接口在公网 nginx 上一律 403，只能在服务器本机调用。
- v1 时期签的旧 token 自动视为 `platform=mac`。
- **校验**：`GET /v1/me` → `{"token_id","user","platform","device"}`；客户端在设置页"测试连接"和启动时调用。
- 客户端把 token 存钥匙串（Windows：凭据管理器）。

## 2. 业务接口
公共可选字段：`session_id`（字符串，客户端生成 UUID，一次录音/会话一个）、`seq`（整数，从 0 起的段序号）、`final`（bool，是否最后一段）、`stream`（bool，默认 false）。服务端原样回显 `session_id/seq`，客户端按 `seq` 拼接。

| 接口 | body 必填 | body 可选 |
|---|---|---|
| `POST /v1/clean` 整理 | `transcript` | `style`(chat/email/code/notes，默认 notes)、`dictionary`(字符串数组)、`context`(前面已整理段落文本，最多取末尾 300 字，用于长录音分段时衔接) |
| `POST /v1/edit` 改写选区 | `selection`、`instruction` | — |
| `POST /v1/translate` 翻译 | `transcript`、`direction`(如"中文→英文") | `style`、`dictionary` |
| `POST /v1/interpret` 会议同传 | `transcript` | `context`(字符串数组，前文)、`dictionary` |

提示词在服务端（源自仓库 `Resources/prompts/*.md` + `styles.json`，拼接方式与现 `Cleaner.swift` 一致），响应里带 `prompt_version`。改提示词请改仓库文件并通知中转同步部署。

### 非流式响应 200
```json
{"text":"整理后的文字","session_id":"…","seq":0,
 "model":"deepseek-flash","prompt_version":"2026-10-30",
 "usage":{"prompt_tokens":812,"completion_tokens":21,"total_tokens":833,"cache_hit_tokens":768},
 "timing":{"upstream_ms":610,"total_ms":618}}
```
空输入（只有语气词）返回 `text:""`，客户端不插入。

### 流式（`"stream":true`）
响应 `text/event-stream`：
```
event: delta
data: {"text":"整理"}

event: done
data: {"text":"整理后的文字","session_id":"…","seq":0,"model":"…","usage":{…},"timing":{"first_token_ms":420,"upstream_ms":…,"total_ms":…}}

event: error
data: {"error":{"code":"upstream_timeout","message":"…"}}
```
短句建议非流式（一次插入，最省事）；长段或改写可用流式边出边显示 HUD，以 `done.text` 为最终插入文本。

### 长录音分段约定
客户端按 Silero VAD 停顿切段 → 每段识别后立即 `POST /v1/clean`（同 `session_id`，`seq` 递增，带 `context`=已整理文本末尾），可并发 ≤3；按 `seq` 顺序拼接，最后一段 `final:true`。服务端无状态，不缓存会话内容。

## 3. 其他
- `GET /v1/ping` 与 `GET /health`（无需鉴权，等价）→ `{"ok":true,"api_version":"1.1"}`。用于 keep-alive 预连接：**按下热键时**客户端就发一次 ping（或保持 HTTP/2/keep-alive 长连接），松开时 TLS 已握好。服务端到 DeepSeek 也维持长连接池。
- 模型、温度、超时由服务端 env 配置（`SC_MODEL=deepseek-flash`，思考关闭，temperature 0.2），客户端发 `model` 字段会被忽略。
- 单次 `transcript/selection` 上限 8000 字，body 上限 64KB。
- 限流：单 token 60 次/分钟。

## 4. 错误码
统一 `{"error":{"code":"…","message":"…"}}`：

| HTTP | code | 客户端处理 |
|---|---|---|
| 400 | `bad_request` | 字段缺失/格式错，属客户端 bug |
| 401 | `unauthorized` | token 缺失或无效 → 提示"请在设置里填写/重新获取 token" |
| 403 | `revoked` | token 已吊销 → 同上 |
| 413 | `too_large` | 超长，客户端应分段 |
| 429 | `rate_limited` | 稍后重试 |
| 502 | `upstream_error` | 模型服务出错，可重试 1 次 |
| 504 | `upstream_timeout` | 超时，可重试 1 次 |
| 503 | `unavailable` | 服务维护 |
| — | （网络错误/DNS/连接拒绝） | 断网：HUD 提示"需要联网"，不做本地兜底，原始识别文本留在历史里 |

客户端超时建议：连接 3s，整体 `4 + 字数×0.02` 秒（同现逻辑）。

## 5. 延迟目标
松开到出字 ≤1.5s：识别 ≤0.3s + 中转往返 ≤1.0s。手段：快模型 deepseek-flash 且关闭思考、system 提示词固定不变（命中 DeepSeek 前缀缓存）、两端 keep-alive、按键即预连接、短句非流式。实测数据见服务部署报告。

### 公网实测（2026-10-30 18:00 美东时间，从美国的 Mac 访问，ECS 在深圳）
- 冷启动（每次新建 TLS 连接）：ping/health 0.6–8s，约 10% 超时；clean 3.2–4.1s；流式首字节约 3.3–3.5s。
- 复用连接后：ping 约 0.6s（≈ 跨太平洋 RTT），clean 1.05–1.43s（第一次 3.3s 含握手）。
- 服务器内部：clean 0.39–0.9s，流式首 token 约 0.59s。
- 结论：国内用户应能达到 ≤1.5s；从海外访问必须保持长连接 + 按键预连接，即便如此 clean 也只能做到约 1.1–1.4s，冷连接会远超目标。海外用户多的话建议加海外节点（地址可配置就是为此）。
