# 调研资料：iOS 识别架构与 C ABI 对接（2026-10-30）

## 结论（给 Typeless 负责人）

1. **识别只放主 App**，键盘扩展不链 `libsaycribe_core` / `SherpaOnnxC`，避免扩展内存与体积爆掉（键盘 RequestsOpenAccess、无麦克风）。
2. **C ABI** 按 `docs/识别接口.md` + `platforms/core/include/saycribe_asr.h`；Swift 用 `@_silgen_name` 对接，真库替换 stub。
3. **sherpa-onnx 在 iOS 只能 shared xcframework**（`sherpa-onnx-sys` 对 ios 强制 Shared）；我们的 Rust 仍出 `staticlib`，App 同时链 `.a` + embed `SherpaOnnxC.xcframework`。
4. **模型**按 `docs/模型下载.md`：SenseVoice int8 + tokens 多源（hf-mirror 优先）+ sha256；`silero_vad.onnx` 首选 `https://saycribe-api.motomotos.com/dl/models/silero_vad.onnx`，GitHub 备用。
5. iOS xcframework 资产在 GitHub release tag **`xcframework`**（不是 `v2.0.1` 路径）。

## 工程结构（对接后）

```
platforms/ios/
  SaycribeApp/          # 主 App：ASR Swift 封装、DictationSession、只此 target 链真库
    ASR/{CABI,Recognizer,Segmenter,ASRTypes}.swift
  SaycribeCore/         # 共享：中转、Token、IPC、ModelDownloader（无识别原生库）
  SaycribeKeyboard/     # 键盘：不链识别
  SaycribeAppTests/     # ABI + 真识别集成测
  SaycribeCoreTests/    # 中转/下载 mock
  Vendor/               # gitignore：libsaycribe_core.a ×2 + SherpaOnnxC.xcframework
  scripts/build-core-ios.sh
```

## 线程与生命周期（契约）

- 识别器进程内一个，启动后台预加载，`num_threads` 手机建议 2。
- 不可并发 transcribe；VAD 分段器每次录音一个。
- 采样率 16 kHz float32；短句可整段，长句 VAD（max_speech 12 s）。
