# Saycribe Linux 客户端 · 技术方案（草案，待负责人批准）
2026-10-30 · Bot E「Saycribe·Linux」

## 1. 总体定位
- 语言：**Rust**，依赖 `platforms/core/` 共享 crate（由 Saycribe·中转与Windows 定接口）。
- core 负责：SenseVoice + Silero VAD（sherpa-onnx）、中转客户端（ping/keep-alive、SSE、seq 拼接、错误码、断网判定）、配置/历史/词典/语气映射。
- `platforms/linux/` 只做平台层：**全局热键、文本注入、取选区、前台 App 识别、HUD、托盘**，分 X11 / Wayland 两个后端，运行时按 `XDG_SESSION_TYPE` / `WAYLAND_DISPLAY` 选择。
- 不做离线整理；断网 HUD 显示"需要联网"，原始识别文本进历史。

## 2. 目录与模块
```
platforms/linux/
  Cargo.toml          # 依赖 saycribe-core = { path = "../core" }
  src/main.rs         # 事件循环、状态机（按下→ping+录音 / 松开→识别→中转→注入）
  src/hotkey/{x11.rs, portal.rs, evdev.rs}
  src/inject/{x11.rs, wayland.rs, clipboard.rs}
  src/selection.rs    # PRIMARY 选区 / Ctrl+C 兜底
  src/appctx.rs       # 前台窗口 WM_CLASS → 语气
  src/ui/{hud.rs, tray.rs}
  src/secret.rs       # libsecret（若 core 不提供）
  packaging/          # .deb / AppImage / Flatpak(后期)
```
trait：`HotkeyBackend`（on_press/on_release）、`Injector`（insert(text)、replace_selection）、`SelectionReader`、`AppContext`。

## 3. X11 后端
| 功能 | 做法 |
|---|---|
| 全局热键 | `x11rb` 的 `XGrabKey`（默认右 Alt / 可自定义）；按住需要 KeyRelease，配合 `XkbSetDetectableAutoRepeat` 去掉自动重复 |
| 写入光标 | 首选：剪贴板(`CLIPBOARD`) + XTEST 模拟 Ctrl+V（终端类 WM_CLASS 用 Ctrl+Shift+V），再恢复原剪贴板（延迟可调）；备选：XTEST 逐字 keysym 映射（同 xdotool type，中文需临时改 keymap，较慢，只做兜底） |
| 取选区 | 读 `PRIMARY`；为空再模拟 Ctrl+C 读 CLIPBOARD |
| 前台 App | `_NET_ACTIVE_WINDOW` → `WM_CLASS` |
| HUD | 无边框、override-redirect、置顶、不抢焦点的小窗（winit+softbuffer 或 GTK4） |
可行性：box 上已有 Xvfb + xdotool，可在 Xvfb 中做自动化注入测试。

## 4. Wayland 后端（难点）
Wayland 禁止客户端全局监听键盘和向别的窗口注入按键，需按桌面分层兜底：

| 功能 | 首选 | 兜底 |
|---|---|---|
| 全局热键 | `xdg-desktop-portal` **GlobalShortcuts**（KDE 5.27+、GNOME 48+ 支持；用 `ashpd` crate），可拿到 Activated/Deactivated → 支持按住说话 | ① 读 `/dev/input` evdev（需用户加入 `input` 组，提示授权）；② 让用户在桌面设置里绑定命令 `saycribe toggle`（只能"按一下开始/再按结束"，非按住） |
| 写入光标 | 剪贴板 `wl-clipboard-rs` 写入 + 模拟粘贴：wlroots(sway/Hyprland) 用 `zwp_virtual_keyboard_v1`（同 wtype）；GNOME/KDE 用 portal **RemoteDesktop** 键盘注入（首次需用户点允许，可保存授权） | `ydotool`（uinput，需 ydotoold + 权限）；再不行只放剪贴板并 HUD 提示"已复制，按 Ctrl+V" |
| 中文直写（可选后期） | `zwp_input_method_v2`/做成 IBus/Fcitx5 前端，commit_string 直接上屏，最稳但工作量大 | — |
| 取选区 | `zwlr_data_control`/`ext_data_control` 读 primary selection（wlroots/KDE）| 模拟 Ctrl+C；GNOME 上可能取不到，则改写功能降级 |
| 前台 App | wlroots: `wlr-foreign-toplevel`；KDE: KWin 脚本/DBus；GNOME: 无公开接口 → 默认 notes 语气，可手动切 | — |
| HUD | `wlr-layer-shell`（smithay-client-toolkit）；GNOME 不支持 layer-shell → 改用桌面通知或普通小窗 | — |
| 托盘 | StatusNotifierItem（`ksni` crate），X11/Wayland 通用；GNOME 需 AppIndicator 扩展 | 无托盘时用设置窗口 |

结论：X11 体验可与 Mac 对齐；Wayland 在 KDE/wlroots 上基本可用，GNOME 上热键/前台识别/HUD 有降级，需在 README 写清楚。

## 5. 录音与延迟
- 录音：`cpal`（ALSA 后端，经 pipewire-alsa/pulse 兼容层在主流发行版都能用）16k 单声道；需要时改用 `pipewire` crate 原生。
- 按下热键：立即启动录音 + 调 core 的 `ping()` 预连接；松开：core 识别（≤0.3s）→ 中转（≤1.0s）→ 注入（≤0.05s），目标 ≤1.5s。

## 6. 对 core 的需求 / Linux 局限（请 Windows 侧定接口时考虑）
1. **录音放哪层**：建议 core 只接收 PCM（`push_samples(&[f32])` / 回调），**采集留在平台层**——Windows 用 WASAPI、Linux 用 cpal/PipeWire；若 core 自带 cpal 也可，但要允许平台层注入音频源（WSLg 下要走 PulseAudio）。
2. **token 存储**：core 定义 `trait SecretStore { get/set/delete }`，Windows 实现凭据管理器，Linux 实现 Secret Service（`secret-service` / `keyring` crate 的 linux-native 后端）；无 keyring 守护进程（WSL、精简 WM）时需兜底：`~/.config/saycribe/token` 0600 并提示。
3. **配置/历史路径**：用 `directories` crate，Linux 走 XDG（`~/.config/saycribe`、`~/.local/share/saycribe`）。
4. **模型路径与下载**：core 提供模型下载/校验接口，模型放 `~/.local/share/saycribe/models`，不进安装包。
5. **语气映射键**：core 的 App→语气映射键用不透明字符串；Linux 传 `WM_CLASS`/app_id（如 `org.gnome.Terminal`），Windows 传 exe 名。
6. **sherpa-onnx 链接**：需 core 支持 Linux x86_64/aarch64 的动态库（或 `sherpa-rs` 静态构建），glibc ≥2.31。
7. **异步运行时**：core 若用 tokio，需暴露非阻塞 API + 流式 delta 回调，HUD 线程不被阻塞。
8. **网络错误分类**：core 需返回枚举（Offline / Unauthorized / Revoked / RateLimited / Upstream / …），平台层只负责展示文案。

## 7. 与 Windows 共用评估
| | Rust（已定） | Python（备选，已放弃） |
|---|---|---|
| 共用 core | 直接依赖同一 crate，中转/识别/VAD/配置完全复用，只写平台层（约 30–40% 工作量） | 需给 core 做 PyO3 绑定或重写一份，两套逻辑易分叉 |
| 分发 | 单二进制 + sherpa 动态库，AppImage/.deb 简单 | 需打包解释器+依赖，体积大、冷启动慢 |
| 延迟 | 无解释器开销 | 启动与加载慢 |
| 平台生态 | x11rb、wayland-client、ashpd、ksni 成熟 | python-xlib/dbus 也够用，但无优势 |

## 8. 测试方案
- **box（本机 Linux）**：单元测试 + Xvfb 里跑 X11 热键/注入集成测试（xterm/xclip 读回）；headless `sway`（`WLR_BACKENDS=headless`）测 virtual-keyboard 注入与 data-control 剪贴板；mock 中转服务器测协议（真 token 到手前）。
- **4060 WSL2 + WSLg**：WSLg 提供 Weston 合成器、Wayland+XWayland、PulseAudio（麦克风经 RDP 转发）。可测：录音、识别、中转、XWayland 下的 X11 注入（在 WSLg 的 Linux 窗口内，如 gedit/xterm）、Wayland 剪贴板。局限：WSLg 的 Weston 不支持 GlobalShortcuts/RemoteDesktop portal 与 virtual-keyboard，**Wayland 全局热键和注入无法在 WSLg 真测**，需另用 VM（如 Hyper-V/VirtualBox 装 Ubuntu GNOME + Fedora KDE）或牙膏哥的真机补测。
- **4060 只读检查结果（2026-10-30 17:48 美东）**：Windows 10 专业版 22H2（19045.3803）；"适用于 Linux 的 Windows 子系统"和"虚拟机平台"功能**均已启用**；`wsl -l -v` 显示**尚未安装任何发行版**；`wsl --version` 不被识别 → 当前是系统内置旧版 WSL，非 Store 版。Win10 要用 WSLg 需 `wsl --update` 升级到 Store 版 WSL 再 `wsl --install -d Ubuntu-24.04`（需授权，可能要重启）。未做任何改动。
